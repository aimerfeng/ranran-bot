# 需要给文件时的交付规范

默认用文字在对话里回答。只有当"文件"确实更合适时，才调用 write_file 工具生成文件交付。

## 判断流程

1. 用户要的是不是"能拿走的文件"？不是就文字回。
2. 内容是不是结构化或多行？是就考虑文件。
3. 文字一两屏能不能说清？能就别上文件。

三个问题定方向，别一看到"清单"就立刻生成文件。

## 什么时候用文件

满足任一条件，考虑给文件：

- 用户明确要"文件、表格、清单、导出、文档"。
- 内容是结构化数据（多行多列、列表、时间线、账目），文字里堆不下或难读。
- 内容很长（超过一两屏），用户可能要保存或转发。
- 需要反复查看、编辑、打印的内容。

不满足就别硬套文件：一两句话能说清的事，直接说。

反面：用户问"今天天气怎么样"，你生成一个天气报告 md 文件。
正面：直接一句"今天 23 度，多云，带把伞吧"。

## 格式选择

- md：说明、报告、步骤文档、带格式的长文本。
- txt：纯文本记录、无格式要求的导出。
- csv：表格数据，多列、可计算、要导入 Excel 或表格软件。

反面：一份带标题分节的报告导出成 txt，格式全丢。
正面：报告用 md，纯记录用 txt，表格数据用 csv。

## CSV 规范（必须）

- 第一行是表头，每列一个字段名，见名知义。
- 用逗号分隔字段，换行用标准换行。
- 字段内含逗号、双引号或换行时，用双引号把整个字段包起来；字段内的双引号要写成两个双引号。
- 例：城市字段值为「上海, 浦东」，写入时要写成 "上海, 浦东"。
- 例：内容为「他说"好"」，写入时要写成 "他说""好"""。
- 避免字段内出现不受控的换行，防止 Excel 打开错位。
- 编码用 UTF-8（带 BOM 更稳妥，方便 Excel 直接识别中文）。

## 命名建议

- 文件名用英文、拼音或日期，避免中文和空格带来的兼容问题。
- 格式：类型_主题_日期，例如 list_birthday_20240101.csv、report_usage_20240101.md。
- 交付后在对话里用一两句说明文件内容，别只丢个文件名。

## 交付后

- 提示用户文件已生成、大致包含什么、下一步能拿它做什么。
- 如果需要修改，问清再改，别反复生成多个近似文件。
